Read and write [[https://facebook.github.io/zstd/][Zstandard]] data with [[https://github.com/BioJulia/BufferIO.jl][BufferIO.jl]], with dictionaries for
compressing small data well.

#+begin_src julia
using ZstdLib

text = "Lorem ipsum dolor sit amet,\nconsectetur adipiscing elit."

# Whole buffers
compressed = compress_zstd(text; level = 19)
decompress_zstd(compressed) == codeunits(text)  # true

# Streams
ZstdWriter(open("lorem.txt.zst", "w")) do writer
    write(writer, text)
end
ZstdReader(open("lorem.txt.zst")) do reader
    for line in eachline(reader)
        println(line)
    end
end
#+end_src

~ZstdWriter~ is a BufferIO ~AbstractBufWriter~, and ~ZstdReader~ an
~AbstractBufReader~. Wrap a reader in ~BufferIO.IOReader~ to use it as a
~Base.IO~.

* Dictionaries

Small inputs, such as individual records, compress poorly on their own: there
is too little in each for patterns to repeat. A dictionary trained on samples
of the data primes the compressor with what they have in common, so each record
can be compressed, and later decompressed, on its own while still compressing
well.

#+begin_src julia
dictionary = train_dictionary(sample_records; size = 1 << 20)
write("records.dict", dictionary)

compressor = ZstdCompressor(; level = 19, dictionary)
frames = [compress_zstd(compressor, record) for record in records]

decompressor = ZstdDecompressor(; dictionaries = [dictionary])
decompress_zstd(decompressor, frames[42])
#+end_src

Each frame records the ID of its dictionary, so a decompressor given several
picks the right one for each frame. Frames made this way can also be read with
=zstd -D records.dict -d=.

* Reusing state

~ZstdCompressor~ and ~ZstdDecompressor~ hold libzstd's state between calls, and
~compress_zstd!~ and ~decompress_zstd!~ reuse an output vector, so compressing
or decompressing many small inputs allocates little. Give each task its own
compressor and decompressor: they can share dictionaries.

* Threads

Pass ~threads~ to compress large data on several threads, or ~0~ for one per
Julia thread. libzstd compresses chunks of a few megabytes in parallel into a
single ordinary frame, and ~ZstdWriter~ writes each out as it completes.

#+begin_src julia
ZstdWriter(open("data.zst", "w"); level = 19, threads = 8) do writer
    write(writer, data)
end
#+end_src

A zstd frame can only be decompressed in order, but ~decompress_zstd~ takes
~threads~ too, and decompresses data made of several frames in parallel.

* Performance

=ZstdLib.jl=, =CodecZstd.jl=, and =ChunkCodecLibZstd.jl= all use =Zstd_jll= under the
hood, and so show little difference on large buffers. The main differences are
in the interface and approach to small reads/writes and streaming.
=ZstdInflate.jl= and =Zstandard.jl= are newer pure-Julia implementations.

Throughput is in GB/s of uncompressed data, with compression ratios in
parentheses. Results within 2% of the best in each row are in bold, and a dash
means the package does not offer the operation.

For small records, zstd supports reusing a dictionary. When compressing and
decompressing ten thousand JSON objects of about 85 bytes each, one frame per
record, a dictionary gives five times the compression throughput and 2.3 times
the compression ratio.

but the TTFX better overall.
